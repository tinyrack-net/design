앱 경계에서 두 테마를 함께 적용해요.

```dart
MaterialApp(
  theme: TinyrackTheme.light(),
  darkTheme: TinyrackTheme.dark(),
  themeMode: ThemeMode.system,
  home: const App(),
);
```

두 테마 모두 Material 3를 사용하고 `TinyrackThemeData`를
`ThemeExtension`으로 설치해요. 사용자 정의 위젯에서 Tinyrack 컴포넌트와
같은 시맨틱 색상이 필요하면 `context.tinyrackTheme`에서 읽으세요. 포커스,
키보드, 제스처, semantics, text scaling은 Flutter 규약을 그대로 따라요.

IBM Plex Sans, Mono, 한국어, 일본어 글꼴 파일 11개를 패키지에 포함해요.
플랫폼 패키징 전 크기는 약 16.4MB이며 앱의 Flutter 에셋 번들에 함께
들어가요. 실행 중에 글꼴을 따로 내려받지는 않아요.

## 페이지 전환

두 테마 모두 모든 `TargetPlatform`에 `TRPageTransitionsBuilder`를 설치해요.
그래서 라우팅된 페이지가 Material의 플랫폼별 기본값을 물려받지 않고 Android,
iOS, macOS, Linux, Windows에서 모두 같은 방식으로 움직여요. 들어오는 페이지는
dialog·drawer와 같은 오버레이 모션으로 닫힘 배율에서 커지며 서서히 나타나고,
pop 할 때는 그 애니메이션을 역방향으로 재생해요. 플랫폼이 `disableAnimations`
를 알리면 전환 없이 페이지를 그대로 반환해요.

특정 화면에만 다른 모션이 필요하면 직접 빌더를 설치하세요.

```dart
ThemeData theme = TinyrackTheme.light().copyWith(
  pageTransitionsTheme: const PageTransitionsTheme(
    builders: <TargetPlatform, PageTransitionsBuilder>{
      TargetPlatform.iOS: CupertinoPageTransitionsBuilder(),
    },
  ),
);
```

## React 패리티 마이그레이션

Flutter에서도 React 컴포넌트와 같은 variant 이름을 사용해요.

| 이전 | 현재 |
| --- | --- |
| Alert와 Badge의 `intent` | `variant: TRStatusVariant.*` |
| 시각·로딩 옵션이 없던 IconButton | `appearance`, `loading`, `loadingLabel` |
| Card의 자유 형식 여백 | `TRCardPadding`, `TRCardVariant`, Card 구성 위젯 |
| 상위 색상만 따르던 Spinner | `variant: TRSpinnerVariant.*` |
| Text의 `role`, `TRTextStyle`, 임의 색상 | `TRTextVariant`와 타입이 지정된 `color`, `align`, `weight`, `truncate` |

`TRTextField`의 Flutter Form 생명 주기 속성은 그대로 사용할 수 있어요.
저장소 루트에서 `pnpm --filter @tinyrack/homepage test:visual-parity`를
실행하면 분리된 React·Flutter 테스트 화면으로 모든 공통 variant를 비교해요.
light/dark와 영어·한국어·일본어를 검사하며, 레이아웃 오차는 CSS 1px
미만이어야 해요. 실제 포인터와 키보드 입력으로 hover, pressed,
focus-visible, disabled, loading, readonly, invalid 상태를 만들고, 120ms
전환을 0, 30, 60, 90, 120, 140ms에서 확인해요. 실패하면 양쪽 렌더링과
diff, 전체 화면, 상호작용 telemetry, geometry JSON을
`packages/homepage/test-results/visual-parity`에 저장해요.
